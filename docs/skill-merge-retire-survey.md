# 自进化技能库的融合与下线策略：跨论文综述

> 2026-10-23。本文汇总自 `AgentRepo` vault 中 Skill-Evolution 主题（87 篇）的深读笔记，
> 聚焦两个具体问题：**已存在的技能怎么融合（merge / consolidation），以及怎么下线
> （retirement / removal）**。所有数字均为他人论文测量，本文只做归纳与对照，不包含
> cap-align 自身的实验结论。
>
> 一个先行的结构性发现：**融合与下线不是同一个问题的两种答案，而是证据等级完全不同
> 的两个操作。** 敢融合的一派靠结构/规则/相似度；有真实执行证据的一派几乎只做下线。
> 原因在可归因性——见 §5。

## 1. 融合（merge / consolidation）

### 1.1 结构压缩派：冗余是"表示债"，用构造保证偿还

共同信念：自进化膨胀的主体不是新知识，而是**重复表示**。SkillZip Pro 实测每轮新增
内容 55%±3% 是重复，可删份额随库龄从 29% 升到 53%；SkillZip 实测未治理时第 5 轮
膨胀到 5.2×。所以正确的手术是结构合并（知识巩固），不是内容过滤（删"不重要"）。

**SkillZip（2608.11079，文档级）** 把技能解析成类型化契约六元组（接口/工作流图/
工具协议/作用域规则/输出契约/证据），四道闸识别四类可复用结构：硬结构阻断（同触发
角色 + 同工具且参数签名兼容才比）→ 哈希精确匹配 → 嵌入近重复 → 冻结关系判定器。
冲突生成**例外候选而非合并候选**。优化是确定性的 MDL 最小化，LLM 只做一次结构化抽取
且从不直接改持久状态。硬覆盖约束保证每个 trigger / workflow edge / tool requirement /
obligation / output field 都必须被覆盖；解析不了的进**锁定残差**逐字保留——失败模式
被有意设计成"压缩不足"而非"静默删除"。结果：压缩 31.2%、均分 0.577（略超未压缩
0.570）、对比 SkillReducer 压缩率高 3.4×、快 3.5×、**0 rollout vs 40–80 次**。
Zip-on-Write 从第 1 轮开启把 16 轮膨胀封顶在 1.6×–1.9×（不压 2.5×–3.7×），
**第 8 轮才开永远追不上**（2.6× vs 1.9×）。

**SkillZip Pro（2608.30785，部署包级）** 把压缩对象升级为带 guard 的路径加权资源图，
四层成本分账（catalog / activation / deployment / path-weighted）。每条删除**必须且只能
挂一条证据 witness**：

- W1 字面包含（可逆）≻ W2 覆盖 witness（确定性内容词覆盖门）≻ W3 蕴含 witness
  （冻结 checker，温度 0，只允许用于不含 prohibition/output/exemption 标记的单元）
- 挂不上就一票否决，无论预测省多少 token

结果：生产内容审核技能删 38.1% 部署 token、10.4% 端到端 token，准确率 89% 落在
未压缩系统自身 88–92% 波动带内；而**无证据保护的 71–76% 压缩丢 18–26 个准确点，
且是单侧假阳性——删掉的恰是"什么情况不该标记"的豁免规则**。witness 阶梯给出这条
路线的上限刻度：W1+W2 只够 13.8%，加受限 W3 到 32.7%，放开根内 W3 到 38.1%。
另有 never-inflate 护栏（审计通过但目标无改进就拒绝压缩、逐字回发），第三个真实库
被整体拒压。

**SkillZip（Tan 版，2608.05604，同名异父）** 在节级程序子图上用类型化图文法挖重复
motif → **可逆移植宏**，每条宏记录类型端口、可执行契约、验证器钩、源码展开指针。
3.46× 压缩率、99.2% 依赖闭包、98.7% 验证器可达；ReZip 增量提升宏需同时满足跨技能
支持 ≥ m、压缩增益 > 0、契约有效三条件。

**共同失效模式**：
1. **解析器即天花板**（2608.11079 自认"上限等于解析器上限"；Tan 版"节切分错则后续
   全错"）。
2. **结构保真 ≠ 行为保真**——结构管住内容不丢，但模型读了压缩文本行为是否真不变，
   只能靠任务分数侧面验证。
3. **表面相似不安全**：两处都"加载数据"可能要求不同输出/验证器。
4. **无重复 motif 时零收益**。
5. 语言偏差：Pro 的词法信号集是英文的，中文生产包 264 个指令单元只认出 7 个必需。

### 1.2 语义聚类派：用"共享规程"造出一个新粒度

**SkillGLoW（2609.02217）** 是唯一纯代表。五视图嵌入共识聚类（签名紧凑 0.30 /
签名冗长 0.20 / 任务指令 0.20 / 轨迹 0.20 / 全文 0.10），关键不在权重而在**按"怎么解"
分组而非"关于什么"分组**；K 由 silhouette 曲线 Kneedle 膝点自动确定。LMB 的 53 个
任务只聚出 K≈5 族。

合并形式是 N 条局部技能 → 每族 1 条**去实例化 global prior**，只留适用条件 / 核心解题
规程 / 常见失败模式；实例细节当负债丢弃，执行时从相邻轨迹差现场再生（永不写回库）。

护栏是 **commit gate**：候选合并结果按 Recall 单独测（保证可归因），锚点
$A=\max(V^\star, V^{ns})$ 再被上轮最高值托底，仅当 $V^{real} \ge A - 0.02$ 才整轮提交，
否则库原封不动。**26 次提交决策拒了 7 次，其中 4 次只凭压缩期软分本会错放**
（MiniMax-M3×LMB 第二轮：软信号 0.283 超锚、真实部署 0.151，−13.2 分）；门保留的库
+14.7 vs 无条件放行 +9.6，**门本身值 5.1 分**。

结果：12/12 run 全正（+17.2pp hard，p=0.000488；局部再生 +18.0pp），库比逐任务池紧
3.6×；零修改迁移 ALFWorld 73.9%→83.9%。失效边界：规程共享稀薄时家族覆盖率崩塌
（SWE×GPT-5.4-mini 仅 9/20 入簇、LMB×MiniMax 14/53）；无 verifier 域整套失效；
合并是一次性有损压缩，单靠语义相似度无法判断"这条细节该不该丢"。

### 1.3 生态治理派：技能间关系是一等公民

**SkillOps（2605.13716）**——**唯一把 merge 列为一等维护操作**。HSEG 图上四种类型化边
（dependency / compatibility / **redundancy** / alternative），合并候选来自 redundancy 边；
规则引擎零 LLM 调用，作用在五元组 Skill Contract $(P,O,A,V,F)$ 上做字段级 patch。
消融：单独 merge 或单独 repair 效果有限，**组合使用才显著**（维护操作间有协同）；
validator 插入是最有价值的单一操作。局限：HSEG 依赖显式接口定义，对纯 NL 技能适用性
有限。

**SkillSmith（2606.01314）**——**唯一有显式 merge 交叉算子**。两条路径：
① 谱系交叉：共享祖先的非支配谱系逐技能合并（谁改了取谁的、都改了取效用高的），
合并前查交互矩阵 $\hat\beta_{ij} < -0.15$ 送扩展回归检查；
② 连续量：从执行日志共现残差免费估计交互矩阵 $\hat\beta_{ij}$（共现 ≥ 5 次才估，
正=互补、负=冲突），喂 Lotka-Volterra 动力学（承载容量 K=20），同一效用同时驱动
检索打分、变异优先级、退休决策。

证据：去生态治理后库膨胀到 >80 组件、准确率从 68% 跌破 35%；FreeTool（无约束改工具）
错误率 14.7% vs 全量 3.2%。局限：冷启动共现稀疏时 $\hat\beta$ 退化为零先验；交互估计
是纯相关性而非因果；**合并失败时只有加一道测试、没有回滚语义**。

### 1.4 检索基质派：不合并，改检索器读什么（边界范式）

**SE-GoS（2609.08228）** 明确声明**从不新增或废弃技能**，节点集固定，只改三轴
（边集合 / 边权 / 描述）。成功轨迹里"检索到的种子 → 真正被用的技能"共现建工作流边；
被检索 ≥2 次却从未被用的头节点入边权重 ×0.5 软剪枝。带**不驱逐护栏**：任何把 agent
实际用过的技能挤出 top-K 的改写一律拒绝。

它对融合研究的价值是一个反证：1,000 技能尺度上界面消融是 null（0.569 vs 0.572，
SE 3.4pp）——瓶颈已在"选择之后"的组合兼容性，正是 SkillZip 一族的问题域。同时警告：
**演化有效剂量只有"一次"**（59.4 → 59.8 → 54.0，边数 863→1,502 后过拟合）。

## 2. 下线（retirement / removal）

### 2.1 贡献衰减驱动（统计检验派）

**Ratchet（2605.22148）** 给出精确理论边界：judge 把失败判为通过的概率
$\ge (1-\tau)/2$ 时，**任何样本量下都不退休任何技能**，且两种错误方向不对称——
误杀（pass→fail）只浪费样本效率，漏判（fail→pass）使驱逐统计量位移、**规则内任何
纠正都无法恢复**。

**Library Drift（2605.19576）** 给出治理配方：每技能贡献分数
$\hat{c}(s)=(\text{successes}-\text{failures})/\text{trials}$ 低于退休阈值 τ，且需攒够
证据阈值 $N_{min}=100$；活跃容量上限 C=50。有界容量 + 退休阈值下，期望 pass@1 不漂移
到低于无技能基线（Hoeffding 容差）。结果：Default 配置增益 +0.328，89 退休 / 50 活跃。

**A4 消融是全篇最重的证据**：$N_{min}$ 从 100 降到 20、τ 收紧到 0.0（"激进退休"），
增益 −0.019（**低于无技能基线**），Hoeffding 偏差 ε≈0.44 时真实贡献 ∈[−0.44, 0] 的
技能因运气不佳被误删，库只剩 2 个活跃技能、路由参与度降至 18.9%——**糟糕的治理比
没有治理还差**。A7 容量翻倍均值相当但方差 ±0.018→±0.110：容量控制方差而非均值。

### 2.2 契约违约驱动

**Skill-V（2610.11781）** 把技能定义为版本化可证伪契约（语义意图 + 流程 + 可执行
rubric + 版本号）。"rubric 判定 vs 任务结果"的**双向分歧驱动边界修订**：rubric 放行
但任务失败 = 边界过宽，rubric 拒绝但任务成功 = 过严。修订提交前过**证据门禁**——在
回放证据上 Disc 不升、FNR 不升、BAcc 不降三条件同时成立（动硬约束还要求至少一项
严格改善）。下线的形态是旧版本被修订版本替换（可追溯、可回滚接口）；检索层三分态
过滤，只有 conf>0.8 的高置信 NOT-APPLICABLE 才删，UNCERTAIN 保留。

量化：无门禁时 46 个提交修订中 9 个回归、成功率 75.0%；有门禁 10/10 全部非回归、
成功率 95.3%。**只增不修的库 68.8% 还不如完全静止的库 73.4%**。库约 200 条
（Skill1 撑满 5000 的 <4%）。

**Skill Drift Is Contract Violation（2605.10990）** 把视角转向外部：技能依赖的包 / API /
配置演化导致**环境契约违约**——下线触发来自外部世界漂移而非使用率。SGName 从文档提取
可执行环境合约（pinned dependency 里的版本号是义务，注释里的是噪音）。无合约 CI 探针
40% 误报；SGName 在 599 个 no-drift / hard-negative 案例中**零误报**
（Wilson 95% CI [0, 0.6]%），违约后修复一轮成功率 10%→78%。

### 2.3 生态位竞争驱动

**SkillSmith** 连续 $T_{ret}=5$ 轮 LV 效用低于退休线即删除。关键设计是**墓志铭**：
退休不直接删，转成（是什么 + 为什么被删）存入反模式记忆，提案与已知反模式动作
相似度 >0.85 触发否决、两次仍命中整个提案作废。−Anti 消融回归率 2.1%→7.6%（3.6×），
veto 三基准触发 14 次拦下 11 个近似重复已退休配置的提案——**退役不留痕就会被重新发明**。

### 2.4 因果反事实驱动：最精细的退役设计

**TrackRL（2610.25126）** 把退役拆成**三种不同语义**：

| 出口 | 条件 | 可逆性 | 语义 |
|---|---|---|---|
| 🗑 移除 | 效用置信上界 < 0（λ=2，95%） | 不可逆，进黑名单 | **有害** |
| 🎓 退休 | 零效用 + mastery 置信下界 ≥ 族基线且 ≥ 0.5 | 可逆（遗忘再生） | **已内化进模型权重** |
| 📦 容量驱逐 | 软容量 300，只驱逐证据充分的非正效用 | 软 | 库压力 |

决策机制是把 GRPO 组改造成**在线随机对照实验**：每个选中技能独立 Bernoulli(1/2)
决定注入，组内形成同任务同策略的处理/对照双臂，**零额外 rollout** 剥离 per-skill
因果贡献（消除搭便车与难度混淆），跨组 γ=0.98 折扣累积。**孵化保护**（证据 <10 次
任何退出机制碰不了）堵住噪声误杀；每次生命周期转移带统计量、可离线回放审计。

量化：ALFWorld 冷启动 skill-free 72.7% vs GRPO 58.6%（+14.1pp，唯一 skill-free 也
超过 GRPO 的方法）；**去掉全部退出机制后 skill-free 从 72.7% 崩到 53.1%**（低于无库
GRPO 的 58.6%）；去掉 per-skill 随机化（退化为 bundle 级）skill-assisted 78.1%→61.7%。

**SLIM（2605.10923）** 是同一思路的轻量版：leave-one-skill-out 估边际外部贡献，
执行 retain / retire / expand 三元操作。最优活跃技能集**非单调**（既非全量也非零）；
LOO 显著优于随机淘汰。自认关键局限：**假设技能之间独立、未考虑组合效应**。

### 2.5 策展学习驱动

**EASE（2609.36746）** 策展器输出 add / modify / remove，条件化在执行器在线行为画像
（滑窗 16 任务）上，GRPO 跨多个冻结执行器联合训练。时序归因双门控决定哪些策展步接受
策略梯度：门1 被编辑技能确实（或反事实会）进入检索；门2 技能辅助动作序列与无技能
参考轨迹的 Levenshtein 偏离超阈值。库规模 57.7→34.0（−41.0%）、token −10.7%。
核心理念："同一技能对强执行器是冗余、对弱执行器是扶手"——**退役判据应是执行器条件化
的**（错配策展器系统性掉 2.3–10.0pp；去行为描述符掉 7.5–9.5pp，静态 model card 只
挽回 1.8–4.6pp）。

## 3. 反面教材：judge 偏差如何静默废掉退役

**The Blind Curator（2607.07436）** 是这个主题最有警示性的一篇。沿 Ratchet 的
贡献退休机制，但把 judge 建模为二元通道。对称噪声只压缩统计向 1/2、优雅退化
（有效阈值 $\tau/(1-2\rho)$、样本预算 $N_{min}\propto(1-2\rho)^{-2}$）；**false-pass
偏置使统计上移，退休触发条件缩窄为 $\bar p(s)\le(\pi_\tau-\rho_{F\to P})/(1-\rho_{F\to P})$，
右侧在 $\rho_{F\to P}=\pi_\tau$ 处归零——越过则任何样本量下无技能被退役**。

实验（Table 1，12 轮 × 3 seeds）：

| judge 状态 | 真退休数 / run |
|---|---|
| clean QC | 1.3 |
| 对称噪声 | 0.7–1.0（保持） |
| false-pass bias（q=0.2/0.45/0.7） | 0.0 / 0.3 / 0.0（全部驱零） |
| 严格 LLM judge（$\rho_{F\to P}\approx0.01$） | 10.3（但实现分歧 0.59） |

两个独立的关键观察：

1. **机制失效对聚合指标隐形**。raw deprecation 计数被 cap-eviction churn
   （库硬上限 C=12 触发的驱逐）撑着，看不出真退休已经归零。**退役治理必须按过程信号
   审计，不能看计数**。
2. **危害呈倒 U**：峰值在半盲 q=0.45（−0.065），全盲 q=0.7 反而 +0.039（连合成任务也
   饿死）。最危险的不是全盲 judge，是半盲。

出路的工程化方案是 **defect-injection 离线审计**：向干净样本注入已知缺陷测 judge 的
$\rho_{F\to P}$（QC-visible 5 类由确定性 grader recall 1.0 抓全；QC-invisible 2 类
语义缺陷——number swap 98.5%、claim negation 92.7% 靠 judge 抓），部署前
go/no-go。注意 Blind Curator 与 Ratchet 构成姊妹篇：Ratchet 给理论边界，Blind Curator
用因果注入验证它，并把不可测的 $\rho_{F\to P}$ 变成部署前可测的审计协议。

## 4. 护栏设计的三条共同模式

**模式 A：证据门槛 + 保护态，"宁可滞留不可误杀"**。Library Drift 的 $N_{min}=100$
（降到 20 即灾难）、TrackRL 的孵化保护 $E_{min}=10$、Skill-V 的三分态只杀高置信、
SkillSmith 的 veto + 回归检查。代价是有害/过时资产滞留（TrackRL 作者自认 $E_{min}$
意味着有害技能会滞留若干训练步）。

**模式 B：退役应当留痕**。SkillSmith 的墓志铭 + veto（−Anti 回归率 2.1%→7.6%）把
"验证过会失败的路"当资产管理；TrackRL 每次转移带统计量可回放审计。两者共同指向
**可审计退役**。

**模式 C：抗 false-pass 偏置的杠杆是阈值 τ，不是更多数据**（Blind Curator 三条设计
规则之二）。TrackRL 给出另一条出路：信号源换成随机化对照 + 客观成败，构造性站在
悬崖安全侧——代价是离开了 verifier-free 域。

## 5. 贯穿性的三条结构性结论

**结论 1：融合与下线正在分工，而非竞争。** 有真实执行证据的一派（TrackRL、SLIM、
EASE）几乎不做合并，只退役。原因在可归因性：**合并把两条技能的功劳和罪过搅在一起，
事后无法用对照实验分开；退役保留了一条清晰的"没有它更好"的证据链**。反过来，执行
证据派在方法论上看不到"两条技能拼起来才有效"——SLIM 自认"假设技能独立、未考虑组合
效应"，TrackRL 的 per-skill 归因天然测不出协同。**这恰好是融合要解决的问题，也是
全谱系最大的一处结构性盲区。** 真正把两者接起来的只有 TrackRL 的准入去重（与现有及
已拉黑技能相似度 < 0.90 才放行——用准入去重替代事后合并）和 SkillSmith 的谱系交叉
合并（有回归检查但无回滚）。

**结论 2：安全保证分三个证据等级，保护的东西不同，缺一不可。**

| 等级 | 代表机制 | 保护什么 | 代价 |
|---|---|---|---|
| 构造保证 | SkillZip 硬覆盖 / Pro witness 阶梯 / SkillGLoW fail-closed recall | 内容不丢 | 解析器即天花板 |
| 统计保证 | TrackRL RCT / SLIM LOO / EASE 双门 | 决策有因果依据 | 功效弱、延迟、verifier 依赖 |
| 模型判断 | 一切 LLM 判官与无门控压缩 | 看起来对 | 最便宜也最脆弱 |

SkillGLoW 的 4/7 误放（压缩期软分 0.283 超锚、真实部署 0.151）与 Pro 的"无保护
71% 删除丢 18–26 点且全为单侧假阳性"是两个独立测出的模型判断上限警示。而 SkillGLoW
击穿了结构派没有正面解决的一点：**结构管住"内容不丢"，执行闸门管住"行为不变"**——
2608.11079 笔记自己的判词。Pro 的 witness 阶梯（W1+W2 13.8% → +W3 32.7% → 38.1%）
则给出构造保证的量化上限。

**结论 3："粒度"是这批论文共同的隐藏自变量，但只有 SkillGLoW 拿它当自变量测。**
三方对照：单文档库 +2.0 / 逐任务池 +10.9 / 扁池+检索 +5.0 vs 家族粒度 +17.2，且结论
分布相依——任务共享同一动作骨架时（ALFWorld）单文档反而唯一稳定为正。同时
SkillFlow（2604.17308）的两条硬结论给融合/下线的评估协议划了线：**技能使用率与收益
完全脱钩**（14 倍使用率差对应 −6.02～+8.43 无序分布），使用率不能当收益代理；结构化
外部化 71.08% vs 纯历史上下文 51.04%（−11.61）。所以该问的不是"哪种策略更好"，
而是"什么任务分布配什么粒度"。

## 6. 留白与证据缺口

1. **verifier-free 域是整个治理体系的悬崖**。TrackRL 的随机化对照需要客观成败信号；
   Blind Curator 证明没有它时 judge 偏置是结构性的、且规则内无法纠正。写作、研究、
   开放对话场景至今没有可信的融合/下线证据。
2. **融合缺随机化证据**。所有合并方法都是一次性观测（无对照臂），SkillSmith 的
   $\hat\beta$ 是相关性、TrackRL 的随机化只测单技能——"合并是否有因果收益"
   在方法论上还没有被测过。
3. **笔记本身的缺口**：Ratchet / Skill Drift / SkillOps / EASE 四篇 vault 笔记较简略，
   操作形式与量化多处"未覆盖"（arXiv ID：2605.22148 / 2605.10990 / 2605.13716 /
   2609.36746），引用前建议查原文。SkillZip（Tan 版）笔记的主表与正文增益口径不一致
   （表里 SkillDAG 36.8 > SkillZip 33.3，正文却写"+6.0 over SkillDAG"）；三篇同名
   SkillZip 中 2608.11079 与 2608.30785 是同团队前后作，2608.05604 是未互引的并行工作，
   综述引用必须分段处理。
