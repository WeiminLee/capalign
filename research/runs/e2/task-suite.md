# E2 task suite — derived from the reference docs feature surface

Machine source of truth: **`task-suite.csv`** (same rows, validated by
`e2-scripts/derive_tasks.py`). This document states the derivation method, the
two tiers, and per-task judging honesty flags.

## 1. Derivation method (reproducible)

The suite is derived **from the reference's docs feature surface only**
(`inventory-heuristics.md` §A.3) — never from the alignment report. The report
is attached to tasks afterwards (Phase 3 of `e2-protocol.md`) and only for
stratified analysis.

```bash
# step 1 — enumerate the reference docs feature surface
find /Users/lwm/code/phonopy/doc -maxdepth 1 \( -name "*.md" -o -name "*.rst" \) ! -name conf.py | sort
# step 2 — per feature page that documents a user-facing capability, derive 1..N tasks.
#   A task is (id, given inputs, expected output, judging method); nothing else.
# step 3 — register each task in task-suite.csv; validate the contract:
python3 e2-scripts/derive_tasks.py research/runs/e2/task-suite.csv --ref-doc-root /Users/lwm/code/phonopy/doc
```

Rules that make the derivation honest:

1. **Non-circularity**: derive from the docs first; consult the alignment
   report only to attach labels, never to pick tasks.
2. **Decidability**: every row states an expected output that is decidable by
   at least one of `gold | cmd | judge`. Rows whose verdict needs a human/LLM
   are explicitly flagged (`judge_method = judge`) and capped at < 30% of the
   real tier.
3. **Traceability**: every task names the doc page (or CLI entry) it derives
   from; the validator checks the page exists under the reference doc root.
4. **Gold provenance**: gold files record how they were produced and are only
   amended through a `log:` entry (`references/evaluation.md` Layer 2).

## 2. Tiers

| tier | purpose | inputs | golds |
|---|---|---|---|
| **mini** (`t-mr-*`) | harness feasibility: run the judging pipeline now, zero-bundle, deterministic | exist in `e2-assets/fixtures/mini/` | exist in `e2-assets/gold/mini/` (generated by the feasibility run, provenance logged) |
| **real** (`r-*`) | the actual E2 measurement on MatDiscovery × phonopy | `to-provide`: fixtures built in Phase 1–3 of the full run | `k8: pending` — generated from a reference executable install (or documented equations) at run time |

Honesty flag per real row: `gold_path = k8: pending` means "not yet produced,
required protocol step before execution"; rows with an empty `gold_path` are
`cmd`-judged (no gold needed).

## 3. Judging contract (summary)

| method | verdict input | who decides |
|---|---|---|
| `gold` | produced files deep-compared vs gold file, numeric tolerance 1e-6 | machine (`e2-scripts/judge_task.py`), deterministic |
| `cmd` | exit code + documented pattern on stdout or a named output | machine, deterministic |
| `judge` | evidence bundle (task, produced files, rubric) — no arm label | human/LLM judge; dual-judge + agreement note | 

Blindness: the judge receives `(task, runner output, gold)`, never the arm
label. `skip` = no staged artifact for that cell (arm c or out-of-selection).

## 5. Coverage and stratification (E2 fairness)

- The suite spans the **whole reference surface** (equivalent/partial/missing/
  unknown as derivable) so arm (c) has passable cells and arm (a)/(b) cannot
  trivially win by construction.
- The alignment report's gap labels are joined on `ref_capability` **after**
  derivation; the join table (task → class/source) is written to
  `e2-assets/task-suite-labels.json` in the full run once the real report is
  pinned. The methodology instance (`references/methodology.md` §3) prefigures
  labels for several rows (e.g. thermal-expansion α partial, NAC absent,
  Grüneisen/group-velocity covered) — those are instance facts to be
  re-validated, not reused as labels.
- Arm budget k = 5 < pool size (expected ~15 for the real pair, methodology §3
  instance: 19 gaps, 3 false catches → ~16 poolable); see protocol §4/§5 for
  the suite-coverage confounder and its control.
